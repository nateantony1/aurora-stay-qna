# AuroraStay hotel policy assistant

Internal proof of concept based on the supplied November low-code notebook and four AuroraStay policy documents. The backend retrieves policy chunks from FAISS and generates grounded responses using gpt-4o-mini. The Streamlit frontend displays an answer with its source chunks by default.

## Run locally

Supply OPENAI_API_KEY to the shell environment without committing it to this repository. Optionally set OPENAI_API_BASE for an OpenAI-compatible endpoint. Run `docker compose up --build -d`. Open http://localhost:8501. The Flask API listens at http://localhost:7860.

Ports bind only to the local computer. The frontend reaches the backend through the Compose service name. The FAISS index must be the trusted index generated by this project, because its metadata file uses Python pickle.

## API

- GET / returns the service welcome message.
- POST /v1/relevant_chunks accepts query and k and returns source chunks.
- POST /v1/answer_with_relevant_chunks returns a generated answer, chunks, and parameters.
- POST /v1/answer returns only the answer.

Default presentation run: k 3, temperature 0, top_p 1, max_tokens 512. Generation uses only retrieved policy information and abstains when the documents are insufficient.

## Evaluation

Ten evaluation questions and ten separate test questions are scored using gpt-4o and the four GEval metrics defined in the supplied notebook. The weighted score is 35% faithfulness, 25% contextual recall, 20% contextual precision, and 20% answer relevancy. Offline AUTO ANSWER means composite score >= 0.75. Individual metric thresholds are 0.85, 0.80, 0.75, and 0.75 respectively.

These benchmark labels do not implement runtime confidence routing. The POC requires staff review. Contextual recall uses expected answers unavailable for arbitrary live questions. Production routing requires a separately validated online mechanism.

## Observed baseline, 6 November 2026

The supplied workflow produced 37 normalized 384-dimensional vectors. The chosen 500-token chunk size with 60-token overlap exceeds the embedding model's 128-token input limit: 31 of 37 chunks exceed that limit. This is a diagnosed baseline limitation, not a recommended production configuration. The evaluation composite classified 5/10 questions as AUTO ANSWER, compared with 4/10 on the separate test set. Only 4/10 evaluation cases and 2/10 test cases met all four individual metric thresholds. Preserve these results as a baseline; rebuild with chunks inside the model limit and table rows that retain column headers, then validate on fresh cases before release.

Docker endpoint checks returned HTTP 200 for the welcome route and all three POST endpoints. The frontend and API ports are forwarded to localhost only. This run uses local Docker rather than GitHub Codespaces.
